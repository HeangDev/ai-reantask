# Role Details

The system has three roles, seeded by `RoleSeeder`: `admin`, `teacher`, `student`. Role names are lowercase and match the `RoleName` enum.

> The permissions below are a proposed design based on your schema and the rules discussed so far. Adjust them to match your real business rules.

---

## 1. admin

**Purpose:** The system manager. Controls users, classes, subjects, and who teaches or studies what.

**How the account is created**
- Seeded by the system (`created_by_user = NULL`). Not available through public registration.
- Status starts as `ACTIVE`.

**What an admin can do**

| Area                               | Permissions                                                                                               |
|------------------------------------|-----------------------------------------------------------------------------------------------------------|
| Users                              | Create teacher and student accounts, edit, change status (`ACTIVE`, `INACTIVE`, `SUSPENDED`), soft-delete |
| Pending students                   | Approve (`PENDING` → `ACTIVE`) or reject (→ `DELETED`)                                                    |
| Roles                              | View roles, set role `ACTIVE` / `INACTIVE`                                                                |
| Classes                            | Create, edit, set `ACTIVE` / `INACTIVE`, soft-delete. Class code is generated by the backend              |
| Subjects                           | Create, edit, set `ACTIVE` / `INACTIVE`                                                                   |
| Class subjects                     | Assign a subject and a teacher to a class (`class_subjects`), pause or remove                             |
| Class students                     | Enroll students into a class (`class_students`), pause or remove                                          |
| Assignments, submissions, analysis | View everything (read-only oversight). Can also correct data if needed                                    |

**Restrictions**
- Only an admin can create or update `classes`, `subjects`, `class_subjects` and `class_students`.
- `teacher_id` must belong to a user with role `teacher`, and `student_id` to a user with role `student`. Both must be `ACTIVE`.
- An admin should not be able to delete or suspend their own account.

---

## 2. teacher

**Purpose:** Teaches subjects in classes, creates assignments, and reviews student work.

**How the account is created**
- Created by an admin (`created_by_user` = admin id). No public registration.
- Status starts as `ACTIVE`.
  **What a teacher can do**

| Area                 | Permissions                                                                                             |
|----------------------|---------------------------------------------------------------------------------------------------------|
| Own profile          | Edit own name, phone, avatar, password                                                                  |
| Pending students     | Approve (`PENDING` → `ACTIVE`) or reject registrations                                                  |
| Classes and subjects | View only the classes and subjects assigned to them in `class_subjects`                                 |
| Class students       | View students in their classes (read-only)                                                              |
| Assignments          | Create, edit, publish, and soft-delete assignments for their own class subjects (`DRAFT` → `PUBLISHED`) |
| Requirements         | Define `assignment_requirements` (type, weight, required or not)                                        |
| Structures           | Define `assignment_structures` and structure rules (files and directories)                              |
| Git                  | Connect a Git account (`git_connections`), link template repositories to an assignment                  |
| Assigning students   | Assign students from their class to an assignment (`assignment_students`)                               |
| Submissions          | View submissions for their own assignments, trigger re-analysis, mark `VERIFIED` or `REJECTED`          |
| Analysis             | Review `analysis_results`, mark `analysis_issues` as `RESOLVED` or `IGNORED`                            |

**Restrictions**
- Cannot manage classes, subjects, or teacher and student assignment to classes (admin only).
- Cannot see or edit other teachers' assignments, unless an admin allows it.
- Cannot create assignments for a subject whose `class_subjects` row is `INACTIVE` or `DELETED`.
- Cannot create or edit admin or teacher accounts.

---

## 3. student

**Purpose:** Learns in classes, receives assignments, and uploads the finished work to the teacher who created the assignment.

**How the account is created**
- Public self-registration (`created_by_user = NULL`), status `PENDING`.
- Or created by an admin, status `ACTIVE`.
- A `PENDING` student cannot log in until an admin or teacher approves the account.
  **What a student can do**

| Area        | Permissions                                                                                                                              |
|-------------|------------------------------------------------------------------------------------------------------------------------------------------|
| Own profile | Edit own name, phone, avatar, password                                                                                                   |
| Classes     | View classes they are enrolled in (`class_students` is `ACTIVE`), with their subjects and teachers                                       |
| Assignments | View `PUBLISHED` assignments assigned to them (`assignment_students` is `ACTIVE`): instructions, requirements, structure rules, deadline |
| Submissions | Submit a commit between `start_at` and `deadline_at`, view own submission history                                                        |
| Analysis    | View own analysis score, requirement results, and issues, with suggestions to fix                                                        |

**Restrictions**
- Cannot connect a Git account or link repositories. Students submit by file upload only.
- Can only see their own data and their own class data.
- Cannot see `DRAFT` or `DELETED` assignments.
- Cannot submit if the assignment is past `deadline_at`, or if their `assignment_students` or `class_students` row is not `ACTIVE`.
- Cannot change `VERIFIED` results or resolve or ignore issues.
- Cannot approve accounts or manage any admin or teacher data.

## Permission summary

| Feature                                                |    admin      |      teacher        |  student     |
|--------------------------------------------------------|:-------------:|:-------------------:|:------------:|
| Manage users                                           |       ✅       |          ❌          |      ❌       |
| Approve `PENDING` students                             |       ✅       |          ✅          |      ❌       |
| Manage classes                                         |       ✅       |          ❌          |      ❌       |
| Manage subjects                                        |       ✅       |          ❌          |      ❌       |
| Assign teacher and subject to class                    |       ✅       |          ❌          |      ❌       |
| Enroll students in class                               |       ✅       |          ❌          |      ❌       |
| View own classes                                       |    ✅ (all)    |    ✅ (assigned)     | ✅ (enrolled) |
| Create and publish assignments                         | ❌ (view only) |       ✅ (own)       |      ❌       |
| Define requirements and structure rules                |       ❌       |       ✅ (own)       |      ❌       |
| Connect Git account                                    |       ❌       |          ✅          |      ❌       |
| Upload a submission (goes to the assignment's teacher) |       ❌       |          ❌          |      ✅       |
| Receive, verify or reject submissions                  |       ❌       | ✅ (own assignments) |      ❌       |
| View analysis results                                  |    ✅ (all)    | ✅ (own assignments) |   ✅ (own)    |
| Resolve or ignore issues                               |       ❌       |          ✅          |      ❌       |

## Login rules by user status

| User status   | Can log in?                      |
|---------------|----------------------------------|
| `PENDING`     | ❌ Waiting for approval           |
| `ACTIVE`      | ✅ (if the role is also `ACTIVE`) |
| `INACTIVE`    | ❌                                |
| `SUSPENDED`   | ❌                                |
| `DELETED`     | ❌                                |
